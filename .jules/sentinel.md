## 2024-06-13 - Remove dangerouslySetInnerHTML to prevent XSS
**Vulnerability:** The application was using `dangerouslySetInnerHTML` in `src/pages/IA.jsx` to render chat messages from AI and user input. The code attempted to format text using a simple string replacement: `msg.content.replace(/\*([^*]+)\*/g, '<b>$1</b>')`. This was unsafe because any raw HTML contained in `msg.content` would also be interpreted by the browser, leading to a Cross-Site Scripting (XSS) vulnerability.
**Learning:** React provides safe and efficient ways to render dynamic formatting without risking XSS. Using array mapping combined with regex splitting (e.g., `content.split(/(...)/g)`) is much safer, as React automatically escapes strings before rendering them.
**Prevention:** Avoid `dangerouslySetInnerHTML` whenever possible, especially when rendering user or dynamically generated content. If text formatting is required, use safe parsing methods that output an array of React elements (like mapping a split string to `<b>` tags) instead of raw HTML strings.
